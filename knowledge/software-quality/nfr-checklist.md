# 非功能测试 Checklist

> 基于 ISO/IEC 25010 软件产品质量模型。
> 使用方法：逐维度判断"该软件是否涉及此项"，涉及则明确指标/约束，设计对应测试。

---

## 1. 性能效率（Performance Efficiency）

- **响应时间**：关键接口/页面在正常负载下的响应时间（如 P95 ≤ X ms）
- **吞吐量 / QPS / TPS**：峰值与日常的处理能力指标
- **并发能力**：最大并发用户/连接数；并发下的数据正确性（无脏读、超卖、重复提交）
- **负载测试**：逐步加压，找出性能拐点与瓶颈
- **压力测试**：超出预期负载时是否优雅降级、是否崩溃、崩溃后能否恢复
- **稳定性/疲劳测试**：长时间运行是否出现内存泄漏、句柄泄漏、性能衰减
- **容量测试**：数据量增长（百万/千万级）后的表现；分页、查询、导出是否仍可用
- **资源利用率**：CPU、内存、磁盘 IO、网络、连接池、线程池在压力下的占用
- **批量/异步/定时任务**：大批量处理、异步队列积压、定时任务执行时长与互斥

## 2. 兼容性（Compatibility）

- **浏览器兼容**：Chrome/Edge/Safari/Firefox 及版本、内核差异
- **操作系统兼容**：Windows/macOS/Linux、Android/iOS 各版本
- **设备/分辨率兼容**：不同屏幕尺寸、DPI、横竖屏、折叠屏
- **数据兼容**：新老数据兼容、历史数据迁移、空数据/脏数据的处理
- **接口/版本兼容**：API 多版本共存、向前/向后兼容、协议升级
- **上下游系统兼容**：与依赖系统、第三方 SDK、外部服务的互操作
- **共存性**：与其他软件同时运行时是否抢占端口/资源

## 3. 易用性（Usability）

- **可学习性**：新用户能否在无人指导下完成核心任务
- **操作一致性**：术语、图标、交互、快捷键、按钮位置在全站是否统一
- **错误提示**：提示是否清晰、定位准确、给出修正建议（而非技术堆栈）
- **可访问性（无障碍）**：键盘可达、屏幕阅读器、色盲友好、对比度
- **反馈与防错**：加载状态、二次确认、防重复点击、可撤销/可回退
- **界面规范**：布局、对齐、字体、留白、刷新/缩放后的表现

## 4. 可靠性（Reliability）

- **成熟度**：主流程在常规场景下的故障率
- **可用性（SLA）**：是否满足 99.9% 等可用性指标
- **容错性**：依赖异常（DB 宕机、第三方超时、网络抖动）时是否熔断/降级/限流
- **异常恢复**：断电、进程被杀、断网重连后能否自动恢复、数据是否一致
- **数据持久化与一致性**：事务完整性、分布式一致性、自动保存、断点续传
- **超时/重试机制**：超时设置是否合理、重试是否幂等、是否产生重复数据
- **灾备**：备份与还原流程是否可用、RTO/RPO 是否达标

## 5. 信息安全（Security）

- **认证**：登录策略、密码强度、防暴力破解、验证码、多因素认证
- **授权/权限**：水平越权（改 ID 访问他人数据）、垂直越权（普通用户访问管理功能）
- **注入类漏洞**：SQL 注入、命令注入、XSS、CSRF、SSRF、XML 实体注入
- **会话管理**：Token 有效期、注销后失效、并发登录控制、会话固定
- **敏感信息**：传输加密（HTTPS）、存储加密/脱敏、日志不泄露敏感信息
- **数据校验**：输入过滤、特殊字符转义、文件上传类型/大小/内容校验、防路径遍历
- **接口安全**：防重放、签名校验、限流、敏感接口鉴权
- **业务安全**：防刷、订单金额/数量篡改、支付逻辑校验
- **安全审计**：操作日志、登录日志、异常行为可追溯

## 6. 可维护性（Maintainability）

- **日志**：日志分级、关键路径可追踪、TraceID、是否便于排障
- **可监控/可观测**：监控告警、健康检查、指标埋点
- **配置化**：开关、配置项是否可热更新；配置错误时的容错
- **可测试性**：是否提供测试桩/Mock、接口可独立验证

## 7. 可移植性（Portability）

- **安装/卸载**：全新安装、覆盖安装、升级、回滚、卸载是否干净
- **部署/环境**：不同环境（开发/测试/预发/生产）、容器化、不同中间件版本的适配
- **可替换性**：组件/依赖替换、标准文件格式导入导出
- **可扩展性/弹性**：水平扩容、自动伸缩

## 8. 合规与本地化（Compliance / Localization）

- **法规合规**：GDPR、个人信息保护、行业监管、数据出境
- **本地化/国际化**：多语言、时区、货币、日期格式、字符集（emoji、生僻字）
- **隐私**：用户授权、数据收集最小化、注销与数据删除

## 9. 无害性 / 安全失效（Safety）— 高危领域

- 系统失效时是否进入"安全模式"，不造成人身/财产损害
- 危险操作的拦截、二次确认、不可逆操作的保护

---

## 使用指引

### 对 Agent 的指引
1. 拿到项目的需求规格 / 功能清单后，逐维度过一遍此 checklist
2. 每个维度判断：该项目是否涉及？若涉及，指标/约束是什么？
3. 涉及的维度，设计对应的非功能测试用例
4. 不涉及的维度，显式标注"不适用及原因"

### 优先级建议（Web API 类项目）
- P0：安全（§5）、可靠性（§4）
- P1：性能（§1）、兼容性（§2）
- P2：可维护性（§6）、可移植性（§7）
- P3：易用性（§3）、合规（§8）
